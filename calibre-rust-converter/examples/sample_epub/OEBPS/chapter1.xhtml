Chapter 1: Introduction to Rust

Rust is a systems programming language that runs blazingly fast, prevents segfaults, and guarantees thread safety. It was created by Mozilla and has gained popularity for its memory safety guarantees without garbage collection.

What Makes Rust Special?

Rust offers several key features that make it unique among programming languages:

  • Memory Safety: Rust prevents common programming errors like null pointer dereferences, buffer overflows, and data races at compile time.
  • Zero-Cost Abstractions: High-level abstractions don't come with runtime overhead.
  • Concurrency Without Data Races: Rust's type system prevents data races at compile time.
  • Modern Tooling: Excellent package manager (Cargo), documentation tools, and testing framework.

Memory Management

Unlike many other languages, Rust doesn't use garbage collection. Instead, it uses a unique ownership system that tracks memory usage at compile time:

fn main() {
    let s1 = String::from("hello");
    let s2 = s1; // s1 is moved to s2, s1 is no longer valid
    // println!("{}", s1); // This would cause a compile error
    println!("{}", s2); // This works fine
}

This ownership system ensures that memory is automatically freed when variables go out of scope, preventing memory leaks and use-after-free errors.

Fearless Concurrency

Rust's type system and ownership rules make it possible to write concurrent code without data races:

use std::thread;
use std::sync::mpsc;

fn main() {
    let (tx, rx) = mpsc::channel();
    
    thread::spawn(move || {
        let val = String::from("hello");
        tx.send(val).unwrap();
    });
    
    let received = rx.recv().unwrap();
    println!("Got: {}", received);
}

This code demonstrates safe communication between threads using Rust's channel system.

Performance

Rust's performance is comparable to C and C++, making it suitable for systems programming, embedded development, and performance-critical applications. The language provides:

  • Zero-cost abstractions
  • Predictable memory usage
  • No runtime overhead
  • Direct hardware access when needed
